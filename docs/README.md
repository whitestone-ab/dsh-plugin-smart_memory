## 3. 格式约定

后续文档一律遵循以下约定，新增文档请照此书写。

### 3.1 元信息头

每篇文档正文之前放一个引用块，内部用无序列表，字段与顺序固定：

```markdown
> - **文档类型**：使用说明 | 设计存档 | 进度日志 | 索引 | 提交记录
> - **创建时间**：YYYY-MM-DD HH:mm (UTC+8)
> - **最后更新**：YYYY-MM-DD HH:mm (UTC+8)
> - **对应代码**：`HEAD <短哈希>`；与代码无关时写「不适用」
> - **适用版本**：npm 包版本；与版本无关时省略
> - **状态**：有效 | 归档 | 冻结
```

列表写法而非软换行，是为了在任何 Markdown 渲染器里都保持逐行显示。

### 3.2 结构与排版

| 项 | 约定 |
|---|---|
| 标题 | 全文仅一个 `#`；章节用 `##`，子节 `###`，最多三层 |
| 编号 | 章节用阿拉伯数字 `## 1.`、`## 2.`，子节 `### 2.1` |
| 表格 | 必须有表头分隔行；列数 ≤ 6；单元格内换行用 `<br>` |
| 代码块 | 必须标注语言（`ts`、`sh`、`bat`、`yaml`、`text`） |
| 行内代码 | 路径、标识符、命令一律用反引号 |
| 日期 | `YYYY-MM-DD HH:mm`，跨时区时显式标注 `(UTC+8)` |
| 强调 | 粗体仅用于结论与警示，不用于普通名词 |
| 空行 | 标题、表格、代码块、列表前后各留一个空行 |
| 换行符 | LF（由 `.gitattributes` 的 `* text=auto eol=lf` 保证） |

### 3.3 引用与链接

- 文档之间的链接用相对路径，不写盘符。
- 示例命令里的绝对路径必须标注为示例，并与本机环境无关。
- 引用提交用短哈希加反引号，如 `f9b226c`。
- 引用结论时给出来源：提交信息、测试名或本文档章节。

## 4. 维护规则

1. **进度日志滚动更新**：[PROGRESS.md](PROGRESS.md) 只保留「当前状态 + 未完成项」，
   已完成的历史条目压缩为里程碑表，避免无限膨胀。
2. **设计存档不再修改**：[DESIGN.md](DESIGN.md) 是原始想法记录，若设计演进，
   在 [PROGRESS.md](PROGRESS.md) 中记录变更理由，不回写存档。
3. **提交记录由 git 派生**：[CHANGELOG.md](CHANGELOG.md) 的条目内容以提交信息为准，
   只做归纳与排版，不改写技术事实。
4. **时间必须可核对**：文档内所有时间都应能在 `git log` 或命令输出中找到依据。
